# P0-03: обычная запись поверх проекта

## Контракт и границы

Продолжение [P0-01](92-audio-device-selection.md) и [P0-02](94-audio-hardware-format.md)
из [очереди готовности](93-core-readiness.md). Обычный Record теперь использует
тот же AUHAL full-duplex путь, что и loop recording. Вход записывается сухим,
проект продолжает звучать. Собственного второго движка, silent media-заглушек
или другого формата проекта нет.

Одна физическая clock domain: вход и выход должны быть одним Core Audio
устройством либо заранее настроенным aggregate. Разные независимые устройства
не соединяются скрытым ресемплингом. Проект остаётся 48 kHz, mono input
дублируется в stereo-файл, захват ограничен 60 секундами и прежним бюджетом
памяти/медиа. Stereo/disk streaming — P0-05; этот срез не снимает лимиты.

## Пользовательский путь

Настроить устройство/каналы, импортировать подложку или оставить пустой проект,
выбрать позицию, нажать Record. Без armed audio track создаётся новая дорожка;
с вооружённой существующей аудиодорожкой создаётся отдельный take, старый comp
не перезаписывается. Сохранённый comp целевой дорожки остаётся в подложке:
автоматическое заглушение старого вокала этим срезом не добавлено.

«Проект → Преролл записи» действует для обычного и loop режимов. Он ограничен
началом проекта: отрицательного времени/count-in перед нулём нет. В преролле
слышны подложка, включённый метроном и включённый MON, но вход ещё не пишется.
Stop в преролле не создаёт пустой клип, Undo-шаг или пустой recovery-файл.

Stop, повторный Record и Space завершают запись и сохраняют её одной операцией
Undo. MON и Stop не блокируются вместе с редактированием проекта. Один обычный
take больше не ошибочно трактуется как набор loop-проходов. При armed track и
включённом цикле прежняя операция разбивает все проходы в один Undo batch.
Новый track без armed target не наследует playback-cycle.

Преролл/обычный take/loop отражаются разными статусами. Общий курсор и MIDI lanes
получают capture-clock через отдельную versioned структуру
`daw_recording_progress`; старый `daw_recording` не меняет размер. Этот курсор
**не** означает измеренную hardware latency compensation: timestamp/offset
согласование записи относится к P0-04.

## Аудиотракт

`MacDuplex` получает вход через `AudioUnitRender`, затем вызывает общий
`DuplexCapture::process`. Порядок: dry input → RecordingWriter SPSC ring;
независимо Renderer → stereo backing; в конце при MON добавляется direct input.
Метроном, подложка и мониторная сумма никогда не направляются в записываемый файл.

Direct MON обходит inserts/master FX/PDC и master fader; это не мониторинг через
цепочку эффектов. Переключение доступно во время take и сглаживается линейным
240-frame (5 ms при 48 kHz) переходом. Сумма ограничивается ±1 на выходе,
перегрузка отражается счётчиком/peak. Некорректные входные значения следуют прежней
writer-policy: NaN/Inf → 0, конечные значения ограничены ±16. Использовать
наушники; прямой мониторинг самого интерфейса DAW не переключает.

В `Renderer::prepare` добавлен необязательный recording horizon. Только
подготовка записи может разрешать пустую подложку и продолжать clock после
последнего клипа. Обычное воспроизведение/экспорт по умолчанию сохранили прежние
ограничения. Loop/tempo/MIDI/эффекты используют существующий renderer.

Callback не получает новых выделений памяти, блокировок или файловых операций.
Захват обрезается точно по оставшейся capacity: преднамеренный лимит не выдаётся
за ring overflow, поздний callback после лимита возвращает тишину. Main-thread
poll завершает и коммитит ограниченную запись.

## Сохранность и жизненный цикл

Перед Stop сверяются текущая revision, expected revision и revision старта.
Устаревший результат не применяется к отредактированному проекту. Отмена,
потеря устройства/ошибка callback останавливают I/O и оставляют подтверждённое
аудио для существующего восстановления. UI не блокирует этот путь модальным
диалогом ошибки. Recovery удаляется только после успешного model commit.
Idle cancel не двигает playhead. Настройки аппаратуры, seek/loop changes и
несовместимый MIDI capture остаются заблокированы во время записи.

Переключение Play → Record пока останавливает старый output и открывает duplex;
это не бесшовный punch-in уже работающего callback. Graph preparation/start
используют прежний control-thread путь; отдельная asynchronous recording
preparation/отмена долгого plug-in prepare не заявляются. Аппаратная задержка,
полный сценарий disk-full/slow writer и длинная запись остаются P0-04/P0-05/P0-06.

## Проверки и воспроизводимость

- `duplex_capture`: настоящий Renderer + RecordingWriter на диске. Блоки
  64/257/4096, точные pre-roll/cap/loop границы, битовое сравнение записанного
  PCM, независимость от подложки/клика/MON, NaN/Inf, плавное включение/выключение,
  пустой проект и отрицательные диапазоны. Сравнения отдельных samples —
  assertions внутри сценариев, не тысячи независимых пользовательских задач.
- `e2e_duplex_recording`: реальный public C ABI → общий callback processor →
  файл → commit/Undo/Redo/SQLite reopen → WAV и независимый PCM reader.
  Устройство заменено **только при линковке этого теста**. У production нет
  environment-переключателя, fake hardware API или отдельного пути commit.
  В экспорте проверяется прежнее сглаживание track-fader, а не ошибочное
  ожидание несглаженного воспроизведения сухого файла.
- `bash scripts/test-recording-ui.sh`: отдельный AppKit harness с настоящим
  DraftApp, NSButton/Stop/MON, общим курсором, записью/Undo/ошибками. Подменяется
  только hardware factory; TCC не запрашивается, begin вызывается после
  смоделированного разрешения. Штатные workspace/export/SDK тесты не заменены.
- Ledger публичного ABI показывает recording hardware gates даже когда API
  вызывается тестовым устройством. Статический call coverage не означает
  физическую приёмку и не процент покрытия ветвлений.

Нативные снимки и логи сохраняются в CI artifacts. Точный head, результаты и
merge фиксируются в PR, а не предполагаются по наличию тестового файла.
Физический интерфейс, microphone permission, disconnect, задержка, прослушивание
и VoiceOver требуют отдельного прогона; issue #20, #10, #13, #14 не закрываются
результатами моделирования устройства.

## Переиспользование

Существующие AUHAL adapter, Renderer, RecordingWriter, Session commands,
Undo/storage/recovery и AppKit controls. Новых библиотек и собственного DSP нет,
кроме ограниченного UX-перехода громкости direct MON.
Первичные системные контракты: [Apple TN2091](https://developer.apple.com/library/archive/technotes/tn2091/_index.html)
и [AudioOutputUnitStop](https://developer.apple.com/documentation/audiotoolbox/audiooutputunitstop(_:)).
