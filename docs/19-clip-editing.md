# Перемещение и обрезка клипа — 0.4.0

14 сентября 2026. Добавлены недеструктивные clip placement/trim, Undo/Redo и сохранение монтажных параметров. Пока поддерживается один клип на дорожке; Split и несколько клипов на одной дорожке ещё отсутствуют.

## Управление

- ⌥ + drag внутри волны перемещает клип.
- Drag за левый/правый край обрезает или расширяет соответствующую границу в пределах исходного аудио.
- При изменении левой границы одновременно меняются позиция на таймлайне, source offset и длительность. Правая граница меняет длительность.
- Escape отменяет активный жест. Одна завершённая drag-операция создаёт одну Undo-команду; preview до отпускания мыши локальный.
- «Клип…» открывает доступные текстовые поля позиции, source offset и длительности в секундах. «Применить» выполняет одну атомарную команду. Поддерживаются десятичные точка/запятая; время округляется к ближайшему кадру 48 kHz.
- Начало редактирования останавливает звук. Следующий Play использует новую геометрию. Обрезанный звук остаётся внутри immutable source и доступен для восстановления границ и Undo.

Длительность таймлайна ограничена 10 минутами. Ограничения импорта прежние: WAV 48 kHz, до 60 секунд на source и 8 аудиодорожек. На экране используется общая шкала с минимумом 12 секунд и небольшим запасом справа. Масштаб фиксирован во время жеста и пересчитывается после commit; zoom/scroll по времени ещё не реализованы.

## Модель и рендер

В track prototype добавлены `clipStart`, `sourceOffset`, `clipLength`. Все хранятся в audio frames. Валидатор требует ненулевую длину, нахождение диапазона внутри source и отсутствие переполнения при проверке конца таймлайна. У пустой дорожки все три поля равны нулю.

`Session::editClip` проверяет revision и инварианты до публикации модели. No-op не создаёт историю. Подготовленный voice содержит копию геометрии и shared immutable PCM. RT определяет, попадает ли текущий timeline frame в интервал клипа, затем читает `sourceOffset + timelineFrame - clipStart`. Вне интервала возвращается тишина. Gain/smoothing/clamp остаются прежними.

Waveform показывает нужную часть cached source envelope в новом месте. 512-bin preview приблизителен на границе очень короткой обрезки; он не используется для вычисления звука. DSP границы sample-accurate. Fades/crossfades ещё нет: монтаж по ненулевой амплитуде может давать щелчки.

## Файлы

Черновик теперь `user_version = 3`: в tracks добавлены `clip_start`, `source_offset`, `clip_length`. Reader принимает v1/v2 и для старого аудио устанавливает start=0, offset=0, length=sourceFrames. Save записывает v3; предыдущие сборки его не открывают. Исходное PCM сохраняется целиком, поэтому trim не уменьшает размер файла.

Это временный формат, не production `.mydaw` с recovery journal или multi-writer locking. Изменения схемы сопровождаются тестами совместимости, но не обещанием постоянного ABI/формата.

## Проверки

Три CTest targets прошли в Debug и ASan/UBSan. Новые сценарии: placement + source trim смещают тестовый transient в ожидаемый output frame; до/после клипа — тишина; invalid/overflow/zero length/revision conflict не изменяют state; Undo/Redo восстанавливает geometry; no-op сохраняет revision; geometry сохраняется и повторно рендерится после SQLite roundtrip; читаются v1/v2.

В UI проверены отображение смещённого клипа, диалог точных параметров и сохранение текущих правок. Сохранённая сессия имела revision 16, start 53 364 кадра (1.11175 с), offset 0, length 576 000 (12 с), gain −4 dB. Эти значения совпали с SQLite после Save. Пользователь одновременно пробовал жесты; это наблюдение текущей сессии, не автоматизированный UI regression suite. Границы/Undo/roundtrip отдельно проверены headless-тестами; полного ручного аудита всех drag/resize/accessibility вариантов нет.

## Инцидент при обновлении запущенной сборки

Старая запущенная версия зависла во время Save. `sample` показал main thread внутри SQLite journal sync → directory open. Предыдущий файл в момент проверки оставался валидным. Причинная связь с заменой подписанного bundle/доступом к Documents не доказана.

Перед завершением зависшего процесса создан отдельный `build/Audio demo - recovered.mydawdraft`: прежнее PCM плюс последняя полностью наблюдаемая модель (одна дорожка Audio check, −4 dB, revision 8). Это ручное восстановление по наблюдаемому состоянию, **не** работа автоматического recovery. История Undo не восстановлена. Исходный файл оставлен отдельно. После перезапуска восстановленный файл открылся, дальнейшие правки успешно сохранились в v3.

Build script теперь собирает в `build/My DAW Next.app`, если `My DAW.app` запущено, и отказывается перезаписывать обе работающие сборки. Проверено: во время сборки Next SHA-256 запущенного executable не изменился. Это устраняет замену работающего bundle; не считается доказанным исправлением всех причин save stalls. В следующем срезе [0.5.0](20-background-storage.md) добавлены фоновый storage, автоматические резервные копии и новый writer; здесь описан исторический инцидент 0.4.0.
