# Смешанный буфер аудио/MIDI на нескольких дорожках

Продолжение [смешанного выделения](arrangement-mixed-groups.md) и
[буфера клипов](96-clip-clipboard.md). Это снимок содержимого проекта, а не ссылка
на исходные индексы и не сериализация audio samples в системный pasteboard.

## Пользовательский путь

1. Выделить аудио и MIDI рамкой или Command/Control-щелчками на разных дорожках.
2. Command-C сохраняет снимок; Command-X сразу удаляет всю группу одним Undo.
3. Выбрать верхнюю целевую дорожку и позицию playhead, нажать Command-V.

Верхняя захваченная строка попадает на выбранную целевую строку. Промежуточные
невыделенные дорожки учитываются в относительных смещениях, но не копируются и
не изменяются. Общая временная опора — самое раннее начало среди всех клипов,
даже когда самый ранний клип расположен на нижней строке.

После успешного Copy/Cut фокус возвращается на верхнюю захваченную строку,
чтобы немедленный Paste не сдвигал группу вниз из-за последнего выбранного клипа.
После вставки выделена вся вставленная группа, а playhead стоит у её полного
конца. Повторное Command-V в этой точке вставляет точно рядом, без округления
назад к сетке; при выборе другой позиции снова применяется обычный snap.

Главное меню, клавиатура и контекстный маршрут используют общий буфер. Проверка
доступности Paste учитывает **все** целевые строки и типы, а не только первую.
Overlap, source slots и общие бюджеты окончательно проверяет домен; отказ
не меняет ни один клип, буфер, playhead, revision или историю Undo. Новые дорожки
не создаются автоматически. Текстовый ввод, запись, MIDI capture, активный жест
и устаревший снимок выделения блокируют мутацию.

## Один буфер, существующая модель источников

Расширен текущий `ClipClipboard`, без второго хранилища: аудиозапись содержит
`Region`, неизменяемый `shared_ptr<const Clip>`, параметры источника и относительную
строку; MIDI-запись содержит копию `MidiClip` и относительную строку. Свойства
клипов, ноты, velocity, channel, source offset, fades, gain/pan, цвет и mute/loop
сохраняются. Routing, инсерты, automation и настройки дорожек не копируются:
вставленные клипы играют через текущую конфигурацию **целевых** дорожек.

Дальнейшее редактирование, перестановка и удаление исходных дорожек не меняют
буфер. Вставка использует текущий порядок целевых дорожек. Undo/Redo не очищают
буфер. Успешный Open/New, явный Clear и уничтожение сессии освобождают его;
неудачное открытие сохраняет. Между документами/приложениями буфер не переносится.

Проверка ссылок и группировка переиспользованы командами Move/Copy/Delete.
Capture создаёт полный снимок **до** удаления. Cut удаляет все исходные регионы
в одном кандидате State, затем вызывает существующий commit. Перемещение
готового буфера noexcept: после commit нет потенциально падающей аллокации
для его публикации. Одна вставка публикует один State и один Undo; отказ на
последней MIDI-дорожке отбрасывает также уже добавленные кандидату аудиоисточники.

## C ABI и совместимость

`daw_capture_selection_clipboard(session, refs, count, cut, expected_revision)`
принимает существующие `daw_clip_selection_ref` version 1. От 1 до 256 ссылок,
без повторов, на одной ожидаемой revision. Cut принимает только 0/1.

`daw_paste_clipboard`, `daw_get_clipboard` и `daw_clear_clipboard` остаются общими.
Размер `daw_clipboard_info` не менялся, reserved остаётся нулём. `kind` теперь
может быть 3 (аудио и MIDI); 0 — пусто, 1 — только аудио, 2 — только MIDI.
Однотипная группа на нескольких дорожках также возвращает kind 1 или 2.

Прежние одно-дорожечные capture/transfer API сохраняют историческую поддержку
hybrid tracks. Новая команда arrangement capture/paste проверяет один видимый
тип на строку: MIDI не вставляется под retained audio source, аудио не скрывает
существующие MIDI-клипы. Выбор обоих типов с **одной** hybrid-строки отклоняется
ещё при Copy/Cut, чтобы не создавать буфер, который невозможно вставить.
Формат проекта, аудиограф, DSP и зависимости не менялись.

## Проверки

- `e2e_mixed_clipboard.cpp`: публичный C ABI, обе размерности смещений, обратный
  порядок ссылок, удаление и перестановка источников, свойства/ноты/routing,
  повторная вставка, Cut/Undo/Redo, ошибки ABI/count/index/revision/target,
  поздние overlap/type/capacity отказы, 256 клипов/16 строк, реальный стереорендер
  и побитное сравнение samples после save/open. Проверяется общий буфер старого
  и нового API, failed Open и clear.
- `e2e_duplex_recording.cpp`: новый API отклоняет Copy/Cut при обычной и loop-записи
  через настоящее ядро захвата с явным simulated-device fixture, не реальный микрофон.
- `workspace_mixed_clipboard_tests.swift`: реальные DAWWindow events и NSMenu
  actions, sparse mixed selection, удаление исходных дорожек, повторный Paste
  вне сетки, общий Undo/Redo, меню всех целей, stale callback, запись, текст и
  сброс документа. Подключён к штатному workspace runner; не подменяет старые тесты.

Результаты исполнения привязаны к точному head в PR и приложенных журналах.
Локальный Swift syntax parse не равен AppKit typecheck или реальному UI-прогону.
Ручные мышь/трекпад, VoiceOver и физическое прослушивание остаются отдельной приёмкой.

## Переиспользование и оставшийся план

Используются текущие Session/ClipClipboard/source interning/Undo, AppKit меню и
responder chain, Foundation/Swift value metadata. API AppKit сверены с официальной
документацией NSMenuDelegate и menu validation; новый сторонний компонент не нужен.

- https://developer.apple.com/documentation/appkit/nsmenudelegate
- https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/MenuList/Articles/EnablingMenuItems.html

Ограничения: до 256 выбранных клипов, 256 аудио/64 MIDI-региона и 16 источников
на дорожку, существующие note/memory/Undo budgets, запрет неожиданных перекрытий.
Следующие этапы: недеструктивное MIDI-окно, range editing, slip/stretch, glue,
ripple, ручки loop/crossfade. Этот этап не объявляет их реализованными.
