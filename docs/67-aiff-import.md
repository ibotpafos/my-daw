# AIFF/AIFC import

Версия 1.39.0 закрывает IMP-01 для второй контейнерной семьи: My DAW принимает mono/stereo **AIFF и AIFC** с PCM-семантикой, а также AIFC со сжатием `fl32`. Границы формата повторяют [версию 1.35](62-variable-rate-wav-import.md): PCM 16/24/32-bit или 32-bit float, частоты 44,1 / 48 / 88,2 / 96 / 192 kHz, длительность до 60 секунд, размер файла до 32 MiB. Результат — тот же канонический immutable stereo Float32 Clip 48 kHz; формат проекта, storage и доменная модель не меняются.

Это форматный срез внутри существующего импорт-пути, а не общий media importer. Типы сжатия AIFC кроме `NONE`/`none`/`fl32`, больше двух каналов, 8-bit и 64-bit float не поддерживаются и отклоняются с точной причиной.

## Поведение

1. Читатель проверяет big-endian структуру `FORM`: допустимы только формы `AIFF` и `AIFC`; точный размер `FORM` (усечение и хвостовые байты отклоняются), duplicate `COMM`/`SSND` отклоняются, chunks идут с pad-выравниванием по спецификации, `SSND` offset и выравнивание кадров проверяются, фактические данные не короче объявленного числа frames.
2. Из `COMM` берутся каналы (mono/stereo), frames, битность и частота (80-bit IEEE extended). AIFC дополнительно проверяет четырёхбуквенный тип сжатия. PCM 16/24/32 нормализуется в Float32, float32 читается как есть; non-finite или выходящие за диапазон выборки отклоняются. Mono дублируется в stereo.
3. Для частот кроме 48 kHz используется тот же `resampleStereoTo48k` (Apple `AudioConverter` вне realtime), что и для WAV; 48 kHz остаётся direct fast path без преобразования. Проектная частота не меняется.
4. Фоновая задача `startAiffImport` использует контракт [версии 1.36](63-background-wav-import.md): фазы reading → decoding → converting → ready, прогресс с кооперативной отменой в ограниченных чанках, по завершении — immutable Clip, job не удерживает session. Отменённый или упавший job не публикует частичный Clip и возвращает фоновые слоты.
5. Storage записывает уже сконвертированный PCM 48 kHz, поэтому после save/open клип не зависит от исходного файла — как и WAV-импорт.

## Bridge и UI

C bridge реализует синхронные revision-aware команды `daw_import_aiff` и `daw_import_take_aiff` (`engine/bridge/daw.cpp`), с той же семантикой ошибок, что и WAV: неудачный импорт не меняет revision, Undo и проект. Публичное объявление в `daw.h` и UI-путь приложения (панель открытия, роутинг по расширению `.aif`/`.aiff`) подключаются текущим изменением и на момент этого среза ещё не проверены через приложение. Фоновый контракт пока покрыт на engine-уровне; отдельные background C API команды для AIFF не введены.

## Проверка и границы доказательств

- Тест не хранит бинарные фикстуры в git: writer в тесте генерирует AIFF/AIFC вручную (big-endian, 80-bit частота) в tmp.
- CTest `aiff_import` (`tests/aiff_import_tests.cpp`): матрица 24 вариантов — 44,1 / 48 / 96 kHz × mono/stereo × {PCM 16, 24, 32-bit, AIFC `fl32`32-bit} через `startAiffImport`: статус Ready, source rate/channels/frames, ожидаемое число проектных frames после resampling (округление к ближайшему), содержимое каналов, mono→stereo дублирование, только finite выборки; `cancelImport` неприменённого job возвращает количество фоновых задач к baseline; битый `FORM` без `COMM`/`SSND` отклоняется.
- Полный прогон этого среза: debug CTest — 11/11, sanitizers (ASan/UBSan) — 10/10. Срез также добавил целевой CTest `dawproject_export` (zip DAWproject содержит `project.xml`, `metadata.xml`, `loss-report.json`, `audio/`).
- Честные границы: формат-декодер и фоновый job проверены headless; UI-путь импорта AIFF через приложение **не проверен** (в работе). Матрица CTest покрывает 44,1 / 48 / 96 kHz — 88,2 и 192 kHz используют тот же `supportedRate`/converter путь, что и WAV, но в `aiff_import` отдельно не проверены. Прослушивание клипов, созданных из AIFF, не проверялось (это общий S1 listening-гейт).

## Следующие границы

- AIFF UI-путь: панель открытия, роутинг по расширению, статус/ошибки в приложении и его smoke-проверка (в работе).
- 88,2 и 192 kHz в матрицу `aiff_import`; отрицательные кейсы для неподдерживаемых AIFC-компрессий.
- Общий прослушивающий acceptance для converted audio (WAV и AIFF) остаётся отдельным физическим гейтом S1.
