# 87. Проверка размера общей памяти VST3 audio helper

## Продолжение инструментального сценария

Сквозной [тест VST3-инструмента](85-vst3-instrument-source.md) на ревизии
`25d3831` прошёл onset/Note Off, MIDI-only граф, сохранение/открытие,
[длительность транспорта](86-midi-transport-duration.md) и WAV-экспорт.
Следующий шаг остановился на `VST3 runtime helper did not become ready`.
Этот красный прогон не считается подтверждением изолированного audio path.

## Несогласованные проверки

В `tools/vst3_runtime_helper.cpp` одноразовый control helper уже принимал
ограниченное дополнение размера POSIX shared memory до страницы Darwin.
Постоянный audio helper вместо этого требовал точного равенства результата
`fstat` логическому `mappingBytes(stateBytes)`. Эти проверки должны использовать
одинаковую политику: размер отображения может включать меньше одной страницы
дополнения, но не может быть меньше логической структуры с payload.

Оба пути теперь используют `validMappingExtent(actual, logical, page)`:
`page > 0 && actual >= logical && actual - logical < page`.
Вычитание выполняется только после проверки нижней границы и не переполняется.
Проверки magic, версии протокола, лимита состояния, fingerprint, размеров
событий и последовательности request/reply не ослабляются. Дополнительный
payload не читается и не публикуется. Формат IPC не меняется.

Шесть `static_assert` покрывают точный размер, допустимое дополнение,
усечённую структуру, лишнюю страницу, нулевую страницу и значения около
`size_t::max`. Реальное исполнение на macOS проверяется тем же обязательным
`vst3_instrument_source`, который ранее остановился до READY. Проверка звука,
смещения, runtime state и отсутствия dry fallback сохранена без ослабления.

## Диагностика

Отказ размера отображения и исключение подготовки инструмента теперь выводят
причину в stderr helper на стадии запуска. Это не callback звуковой карты:
новых записей в лог, ожиданий или блокировок в audio callback не добавлено.

Первое подтверждение исправления публикуется в PR #7 только после исполнения
CI на новой ревизии. Этот документ описывает причину и проверяемый контракт,
а не объявляет новый прогон успешным заранее. Изоляционная аудиопроверка
остаётся paced-тестом с паузой на тестовом потоке, не измерением realtime
deadline или физического аудиоустройства.

## Переиспользование

Использована существующая политика control mapping и стандартные POSIX API;
новой IPC-библиотеки, протокола, DSP или собственного аллокатора нет.
