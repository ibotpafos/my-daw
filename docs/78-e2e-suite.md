# 78. Сквозные e2e-сценарии

## Назначение

Белые CTest-тесты (`tests/*.cpp`) проверяют каждый срез по отдельности: домен, рендер, хранилище, мост. Этот набор — **чёрноящикные сквозные пользовательские сценарии** (`tests/e2e/`): они гоняют продукт ровно через тот же публичный C ABI (`engine/bridge/daw.h`), что и macOS-приложение, и проверяют долговечные артефакты — файлы черновиков, `.mydawzip`, экспортированные WAV — собственным независимым кодом. Если ABI врёт, сценарий красный, даже когда все узкие тесты зелёные.

## Харнес

`tests/e2e/e2e.hpp` — единственная общая библиотека сценариев. Правила:

- **Никаких инклюдов движка.** Только `daw.h` + std. Сценарии не могут подсмотреть внутренности.
- **Независимые WAV/AIFF ридер и писатели.** Проверка экспорта собственным разбором байтов, а не `daw::readWav`: движок может солгать себе, харнесу — нет.
- **`dumpOf()`** читает весь долговечный проект обратно через ABI (дорожки, регионы, тейки, отправки, MIDI-ноты постранично, линии автоматизации, шины, вставки, темпо, размеры, маркеры) и даёт полное сравнение с читаемым diff — это опора всех save/reload/pipeline-проверок.
- **`CHECK_OK`/`CHECK_REJ`** проваливают тест с текстом ошибки из `daw_error` — лог сценария читается как пользовательский сбой. Ожидание отказа также требует, чтобы человекочитаемая ошибка осталась.
- Ожидание фоновых джоб ограничено по времени и именуется при таймауте.

## Запуск

```sh
./scripts/run-e2e.sh                     # debug-пресет: сборка + ctest -L e2e + ledger
```

или вручную:

```sh
cmake --preset debug
cmake --build --preset debug -j 8
ctest --preset debug -L e2e --output-on-failure   # только e2e-набор
ctest --preset debug --output-on-failure          # всё вместе
```

Sanitizers (CI-гейт): `cmake --preset sanitizers && cmake --build --preset sanitizers -j 8 && ctest --test-dir build/sanitizers -L e2e --output-on-failure`.

Физическая дуга транспорта (реальное устройство, тихий синус в динамики) включается явно:

```sh
DAW_E2E_DEVICE=1 ./build/debug/e2e_transport
```

По умолчанию она пропускается, поэтому headless-CI остаётся зелёным; на машине с выходным устройством гейт обязан проходить.

## Ledger покрытия ABI

`python3 scripts/e2e_coverage.py` перечисляет каждую функцию `daw.h` и где она прогоняется: e2e-сценарий, белый тест, либо именованный ручной гейт. Ключ `--strict` падает, если функция не покрыта e2e и не загейчена политикой — это CI-гейт полноты.

## Заметки движка, найденные сценариями (всё измерено по байтам)

- СТЕМЫ каждого stem-экспорта покрывают полный диапазон проекта, а не длительность дорожки; приглушённые и пустые дорожки файлов не дают.
- Мастер-выход зажат в [-1, 1], поэтому «горячий» обход лимитера измеряется как ровно 1.0; честное доказательство лимитера — бит-идентичность bypass и engaged при единичном усилении и 0.00098 против 1.0 при +12 дБ.
- Undo/redo сами порождают ревизию: сравнения дампов сверяют содержимое, арифметику ревизий проверяют отдельно; откат к нулевой ревизии невозможен — эталон сравнения это новая сессия.
- Дефолтный размер такта — 4/8, а не 4/4; комментарий в `daw.h` и docs/41 исправлены по факту сценария.
- На не-Apple `daw_scan_supported_au` возвращает rc 0 с нулевым счётчиком (честный stub, не ошибка); с текстом отказывают только `daw_get_supported_au`, `daw_add_master_au`, `daw_add_insert_au`.
- Автоматизация интерполируется линейно по децибелам между точками — сценарий сверяет RMS окон с аналитическим предсказанием.
- Открытый жест автоматизации (любого вида) блокирует ВСЕ revision-проверяемые команды, включая undo/redo; а неудачный `daw_end_automation_gesture` (stale revision или end_frame раньше последнего сэмпла) оставляет жест открытым — клиент, проигнорировавший rc 1, блокирует себе сессию до good end или cancel. Проверено e2e.
- Пустой жест (begin+end без записей) не стоит ни одной ревизии; записи жеста на одном фрейме заменяют друг друга (порядок неубывающий, не строгий).
- Импорт AIFF/AIFC и хостинг AU живут только на Apple; кроссплатформенный хребет e2e — 48 kHz PCM WAV, поэтому Apple-секции сценариев стоят под `#ifdef __APPLE__`.
- Три tail-политики экспорта дают **одинаковую** длительность на графе без плагинов: docs/60 различает их только по бесконечному VST3-тейлу, а хост AU сообщает tail 0. Разница политик достижима лишь с реальным бесконечным хвостом — это физический гейт vendor-матрицы, а не e2e; сценарий сверяет честность механизма (preview == фактический рендер, предел 30 с, матрица валидации), а не имитирует разницу.
- `daw_set_loop` и границы петли из транспорта не влияют на экспорт вовсе: петля не тратит ревизию, полный экспорт с включённой петлёй бит-идентичен, `transport.duration` — длина проекта. «Экспорт по петле» в UI = передаваемые границы в `daw_begin_export_range`.
- `daw_get_master_loudness` гейтит только `struct_size` и игнорирует переданный `version` (всегда отдаёт echo 1), тогда как `daw_export_options` и `daw_get_export_tail_summary` версию проверяют. Асимметрия зафиксирована как есть.
- Оффлайн-экспорт не питает живую телеметрию: после экспорта `daw_get_channel_meter` = 0/0, а `daw_get_master_loudness` = −200/−200 при `live=0`. Файловый метр, который видит экспорт, — `daw_measure_wav`.

## Границы (что остаётся ручным)

Микрофон и TCC, полный full-duplex цикл с реальным железом, прослушивание и петля-замеры задержки, vendor-матрицы сторонних AU/VST3, VoiceOver — как зафиксировано в [66 приёмке альфы](66-alpha-acceptance.md). e2e-набор намеренно не открывает устройства ввода: см. `daw_record_start*` в ledger.

Отдельная известная граница: **сборка `daw_core` под Linux/g++ в этом дереве сломана до e2e-набора** — `daw::Vst3ScanCacheEntry` определён только в Apple-заголовке `platform/macos/vst3_scan_cache.hpp`, но используется в общеплатформенном `bridge/daw.cpp`, а `-Werror=misleading-indentation` (GCC строже Clang) даёт десятки ошибок в кодах движка. Матрица ubuntu в CI ещё не запускалась удалённо, поэтому дефект не проявлялся. Сценарии e2e написаны кроссплатформенно (весь Apple-only код под `#ifdef __APPLE__`), починка движка — отдельная задача вне объёма этого документа.

## Добавление сценариев

Новый файл `tests/e2e/e2e_<journey>.cpp` подхватывается CMake автоматически (`CONFIGURE_DEPENDS`), получает метку `e2e` и `TIMEOUT 300`. Один бинарник = одно пользовательское джорни; при добавлении обновить таблицу состава выше и (при появлении новых ABI-вызовов) ledger.
