# Буфер клипов, вырезание и перенос аудиоисточников

Продолжение [редактора аранжировки](95-arrangement-editing.md). Этот срез снимает
ограничение «скопировать заново после каждой вставки», заменяет отложенный перенос
на настоящее вырезание и разрешает удалить последний аудиорегион. Это не полный
паритет Studio One / Logic и не реализация mixed-track clipboard. [Групповые операции](arrangement-mixed-groups.md) реализованы отдельно.

## Пользовательский путь

Выбрать клип или группу (включая разные типы и дорожки) → Command-C → выбрать пустую
или совместимую дорожку → поставить playhead → Command-V. Повторная вставка не
требует повторного копирования. Изменение нот, цвета, громкости или удаление
исходного клипа/дорожки не меняет захваченный снимок.

Command-X удаляет выделение сразу, одной транзакцией и одной записью Undo.
Command-Z восстанавливает оригиналы, но оставляет снимок в буфере. После Undo
вырезания Command-V делает новые независимые клипы, а не удаляет оригиналы снова.
Неудачная вставка, например из-за перекрытия, не расходует Undo и не очищает буфер.

Главное меню, меню аудиоклипа и клавиши аранжировки используют один маршрут.
Проверки текстового ввода, записи, MIDI capture, gesture ownership и актуальной
revision сохранены. Снимок переживает изменения проекта; индексное выделение
и незавершённый drag по-прежнему обязаны соответствовать актуальной projection.

Новый/успешно открытый документ очищает и core clipboard, и метаданные UI.
Неудачное открытие не меняет ни проект, ни буфер. Буфер документный, не системный
NSPasteboard и не межпроектный обмен; он намеренно не сохраняется в проект.

## Модель и владение

`ClipClipboard` содержит immutable-снимок. Аудио: полные `Region`, правильный
источник выбранного take/base, имя и исходная временная опора; samples удерживаются
через существующий `shared_ptr<const Clip>`. MIDI: копия списка нот и свойств
клипа. Начала нормализованы относительно самого раннего выделенного клипа;
расстояния и паузы внутри группы сохраняются. Исходники не декодируются повторно
и не копируются в каждом paste.

`captureClips`, `pasteClips`, `transferClips` переиспользуют snapshot/validate/commit
существующей Session. Подготовка нового буфера завершена до commit вырезания;
move/optional publication не бросает исключений. Все изменения целевой дорожки,
включая присоединение источников, сначала выполняются в копии состояния. Ошибка
в середине группы не оставляет часть вставленных клипов или «лишний» take.

Для чужого аудио переиспользуется уже сохраняемая таблица источников дорожки:
base + takes. Источник с той же pointer identity и source start переиспользуется;
новый присоединяется один раз. На пустой дорожке он становится base. Выборка,
offset, fades, gain, pan, color, mute и loop остаются свойствами региона.
Имена/эффекты/маршрутизация дорожки назначения не заменяются свойствами источника.
Это ограниченный source adapter, не новый глобальный пул медиа и не превращение
внешнего файла в синхронный import внутри жеста.

Нулевое количество аудиорегионов теперь допустимо. Исходники/тейки не удаляются:
это сохраняет comping и возможность Undo без побочного изменения FX/routing.
На аудиопоток не добавлены allocation, locks, destruction или file I/O.

## C ABI

- `daw_capture_clipboard`: track, audio/MIDI flag, 1…256 индексов, copy/cut,
  expected revision. Флаги строго 0/1, индексы проверены/дедуплицированы.
- `daw_paste_clipboard`: target track, frame, expected revision; одна транзакция.
- `daw_get_clipboard`: bounded `daw_clipboard_info`, kind/count/span; без нот/samples.
- `daw_clear_clipboard`: освобождает снимок на owner thread; не редактирует проект.

C ABI проверяет recording/MIDI capture, stale revision, active gestures, null и
struct size. Неуспешный захват сохраняет предыдущий clipboard. Успешный copy
не изменяет revision и не останавливает транспорт; cut/paste сбрасывают транспорт
как существующие команды монтажа. UI также хранит только relative geometry/kind
и document UUID, но не источник, ID оригинального клипа или старую revision буфера.

## Совместимость и пределы

Существующая схема проекта/SQL не изменяется; старые проекты по-прежнему читаются.
Новая семантика разрешает пустую аудиодорожку с сохранённым источником: старые
бинарники, требующие минимум один регион, могут отклонить такой новый проект.
Обратная совместимость новых empty-region проектов со старыми бинарниками не
объявляется. Save/open и audio export проверяются в текущем приложении.

Пределы остаются: 16 base/take-источников и 256 аудиоклипов, 64 MIDI-клипа на
дорожку, существующие бюджеты памяти/нот/Undo и правила перекрытий/crossfade.
Буфер дополнительно удерживает исходники одного захвата до его замены/очистки;
он не является неограниченной историей. Отказ capacity/overlap не меняет проект.

Смешанные clipboard-группы добавлены в [отдельном этапе](arrangement-mixed-clipboard.md):
`daw_capture_selection_clipboard`, общая временная опора и относительные строки.
Старый `daw_capture_clipboard` остаётся совместимым адаптером одной дорожки.
Настоящий media pool, nondestructive MIDI trim, ripple/range/slip/stretch/glue
пока не реализованы. Mixed drag/nudge/Delete/duplicate и MIDI split через ноту
добавлены в [следующем срезе](arrangement-mixed-groups.md).
Не добавляются притворные fallback-операции с частичным commit.

## Проверки и повторное использование

`clip_clipboard_tests.cpp`: модель, независимость снимка, свойства, shared source
identity, take remapping, пустая дорожка, повторная вставка, Undo/Redo, source-slot
capacity и отказ всей транзакции.

`e2e_clip_clipboard.cpp`: реальный публичный C ABI → core → Save/Open → WAV.
Независимый WAV-reader проверяет амплитуду/панораму вставленного аудио и тишину
в паузе после удаления оригинала; повторное открытие сравнивается по samples.
Также MIDI-ноты/слои/цвета, группы, invalid/null/stale/gesture, failed Open,
очистка буфера и one-command/one-revision.

`workspace_clipboard_tests.swift`: настоящие `DAWWindow.sendEvent`, main menu
validation/action и C ABI: копирование MIDI-группы, изменение/удаление оригиналов,
повторная вставка, ошибки перекрытий, cut/Undo/paste, пустая audio lane, UUID reset.
Включён в существующий workspace runner, не вместо старых регрессий.

Переиспользуются C++20 value containers/shared_ptr, существующий Session Undo и
AppKit NSMenu/NSWindow routing, а не сторонний editor framework. Поддерживаемый
production SDK — macOS 14+, Swift 6. Первичные системные контракты:
[валидация меню AppKit](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/MenuList/Articles/EnablingMenuItems.html),
[NSMenu](https://developer.apple.com/documentation/appkit/nsmenu).
Новой runtime-зависимости нет. Для локального Linux-прогона использован реально
установленный libsamplerate 0.2.2 с API header той же версии, не DSP-заглушка.
Нативный прогон относится только к проверенному CI head; физические мышь/трекпад,
VoiceOver и реальное аудиоустройство остаются ручной приёмкой.
