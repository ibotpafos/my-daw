# 70. Instrument-source: слышимые MIDI-дорожки (срез 1.42.0)

## Что это
MIDI-дорожка без единого аудио-файла становится полноценным голосом рендера: тишина на входе цепочки, ноты на входе инструмента, звук на выходе цепочки. Собственных тембров нет — их дают сторонние VST3/AU-инструменты (решение владельца 2026-09-15).

## Правило instrument-voice (`engine/audio`)
Трек без аудио-клипов активен в графе (голос + цепочка инсертов), если `midiClips` непусты или инсерты непусты; обходимый/непроизводящий инсерт честно рендерит тишину. Совсем пустой трек — не голос. Гейт проекта: ошибка только если нет ни аудио-голосов, ни инструмент-голосов — текст 'Import audio or add a MIDI/instrument track'. Длина проекта теперь включает MIDI-клипы всех треков (position/loop-валидации покрывают MIDI-only). Нулевой буфер блока переиспользует существующий zero-fill workspace — ноль новых аллокаций в RT; хвосты инсертов попадают в PDC/serialTail, потому что трек больше не исключён из activeGains.

## Доставка
MIDI-события блока (срез 68) идут шестым аргументом `process()` всем звеньям цепочки; для VST3-managed-runtime это протокол v2 изоляции (frame-accurate, ≤512 событий/блок). Доказательство loop-wrap на реальном графе: тест с 16-голосным синус-инструментом (тестовый `PreparedEffect`, production-код не затронут; шов `insertFactoryForTest` — control thread, в проде null) показывает затухание после принудительного off на петле — без `wrapCutOffs` нота висела бы вечно.

## GUI
Play активен для MIDI-only проекта с клипами (`hasMidiContent` через `daw_get_midi_clip_count`; экспорт сознательно остался аудио-only). Секция Inserts общая для всех дорожек — на MIDI-дорожку инструмент вставляется тем же браузером; AU-инструменты (subtype `aami`/`auia`) помечены «инструмент · experimental», VST3-вкладка носит warning-лейбл, потому что C-мост пока не передаёт Instrument-флаг сканера (field gap: `daw_vst3_component` без flags — отдельное маленькое изменение). Бейдж «♫ MIDI», статус-подсказка 'добавьте ноты и инструмент'.
