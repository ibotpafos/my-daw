# Проектный архив .mydawzip (1.60.0)

Черновик My DAW самодостаточен: аудио живёт BLOB-ами в SQLite-файле (docs/22-*), поэтому «собрать проект» — это один файл-архив для пересылки. `engine/storage/project_package.{hpp,cpp}` упаковывает сохранённый черновик в ZIP32 со stored-записями (тот же формат, что пишет `writeZipPackage` для DAWproject):

- `project.mydawdraft` — байт-в-байт сохранённый черновик;
- `manifest.json` — `{format:"mydaw-package",version:1,entry,draftVersion,draftBytes,createdUtc}`; номер формата черновика читается из заголовка SQLite (user_version, big-endian @60) без открытия БД;
- `README.txt` — человекочитаемая подсказка.

Извлечение (`extractProjectPackage`) перечитывает архив собственным stored-ридером (`readZipEntry`: EOCD-скан, центральный каталог, локальные заголовки, CRC32) и публикует цель атомарно (temp+rename). Гейты: не-SQLite цель/содержимое — «not a My DAW database», чужой архив — «Archive is not a My DAW package», битый байт — «ZIP entry CRC mismatch», отсутствие файла — «File not found». Потолок 1 ГБ.

Мост: `daw_package_project(session,draft,zip)` и `daw_extract_package(session,zip,target)` (ошибки движка проходят как сообщения; NULL/отсутствующие пути отвергает `pure_c_bridge`). UI: «Файл → Упаковать проект…» (сохранённый черновик обязателен — до сохранённого состояния архив не собирается) и «Файл → Открыть проект из архива…» — извлечение рядом с архивом в `имя.mydawdraft` (при коллизии `имя.mydawdraft-2…`) и немедленное открытие общим путём `openDraftFile`.

CTest `project_package` (18-й, debug; в sanitizers/TSan тоже): упаковка→распаковка→`readDraft` с панорамой и аудио побайтово, манифест с draftVersion 22, повторное извлечение поверх цели, отказ чужого архива/битого CRC/несуществующего черновика/не-ZIP. Внешняя валидация: системный `unzip -t` на этом же архиве — OK по всем трём записям (проверено вручную один раз; в CI не входит).

Пределы: распаковка не проверяет семантику SQL-дампа глубже магических байтов и не песочничает пути записей (формат пишет только наш движок); «collect or keep separate» для внешних медиа не нужен — внешних медиа нет. Совместимость старых версий приложения: zip-ридер принимает только stored-записи (наш писатель ничего другого не создаёт).

Родственный формат: `.mydaw/` (директория-пакет по `specs/project-manifest.schema.json`) в движке ещё не реализован — `storage.cpp` прямо называет SQLite-черновик отдельным экспериментальным форматом. `.mydawzip` — временный портативный конверт для пересылки сохранённого черновика, а не заявка на роль проектного формата.
