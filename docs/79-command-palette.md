# Command Palette

## Источник и статус

[Продуктовая документация](01-product.md) требует палитру команд с клавиатуры.
Версия реализации — **1.74.0**, PR #8. Палитра доступна через «Вид → Палитра команд…» и `⌘K`.
Следующий пункт из этого документа — последние/частые команды и разделение выдачи — реализован вторым срезом.

## Поведение

`⌘K` открывает палитру из главного окна; повторное сочетание закрывает её из самого окна палитры, в том числе при активном поле поиска. Физическая клавиша K работает и в RU-раскладке, Caps Lock не мешает. Удержание сочетания не переключает окно многократно. Активная IME-композиция в исходном поле не прерывается.

Вверху находятся поиск и переключатель **Все / Недавние / Частые**. В «Все» пустой запрос сначала показывает ранее вызванные доступные команды, затем остальные в порядке меню. В «Недавние» действует порядок последнего вызова; в «Частые» — число вызовов, при равенстве — давность. Непустой запрос ранжируется по текстовому совпадению: история не поднимает менее подходящую команду выше точного результата.

Поиск учитывает название, путь меню и shortcut, несколько слов и сокращения с сохранением порядка букв. Это не исправление произвольных опечаток и не распознавание естественного языка. Нормализация использует фиксированную locale, а не настройки текущего компьютера. Выдача ограничена 80 строками, запрос — 256 символами.

Стрелки и Return/Escape принимаются через `NSControlTextEditingDelegate`, поскольку во время ввода первым responder является field editor, а не `NSSearchField`. IME получает свои команды без перехвата. При фокусе на таблице доступны Return/Escape и обычная табличная навигация; двойной клик работает только по реальной строке.

## Источник действий и повторная проверка

Источник — `NSApp.mainMenu`, а не второй реестр команд. Видимые enabled leaf-команды индексируются после `NSMenu.update()` с учётом скрытых/недоступных родительских пунктов. Ограничения обхода: 16 уровней, 2048 команд. Nil-target действия разрешаются **до** передачи фокуса поиску.

Перед вызовом палитра закрывается, возвращает исходное окно и responder, обновляет меню и проверяет, что прежние пункт, selector, target и tag по-прежнему доступны. Удалённый, скрытый, отключённый или перенаправленный пункт не выполняется и не попадает в историю. Это проверка menu-context, а не snapshot/revision-транзакция проекта; дальнейшие проверки остаются обязанностью существующей команды.

При потере фокуса палитра отсоединяется без принудительного возврата фокуса. Закрытие главного окна удаляет его палитру. Ссылки на элементы выдачи освобождаются при закрытии; target хранится слабо.

## Локальная история

История использует `UserDefaults`, ключ `commandPalette.usage.v1`, версионированный JSON. Не более 100 уникальных записей; если JSON-экранирование длинных идентификаторов превышает 256 KiB, старейшие записи удаляются до сохранения. Собственная сохранённая история всегда укладывается в лимит чтения. счётчик насыщается на 1 000 000. Повреждённый JSON, неизвестная версия или данные свыше 256 KiB дают пустую историю; неверные записи и дубликаты отбрасываются. «Очистить историю» удаляет только этот ключ.

Предпочтительный ID — `NSMenuItem.identifier`. Иначе используется однозначное кодирование полного пути меню, названия, selector и tag, без номера строки. Перестановка посторонних команд не меняет ID. Изменение названия/локализации без явного identifier создаёт новую запись; одинаковые fallback-ключи различаются порядком в текущем меню. История хранит только идентификаторы и счётчики, не строки поисковых запросов и не исполняемые closures. Fallback-ID включает название/путь команды.

Запись добавляется только после успешного **dispatch** `NSApp.sendAction`. Это не подтверждение завершения операции: открытый диалог экспорта пользователь всё ещё может отменить. Открытие, поиск, смена вкладки, Escape и отказ повторной проверки историю не увеличивают. Недоступные команды из сохранённой истории не восстанавливаются в выдаче.

Палитра и история не вызывают C project bridge, не меняют проектный формат, revision или Undo. Само выбранное действие использует прежний штатный путь выполнения.

## Проверки

`bash scripts/test-command-palette.sh`:

- На Linux и macOS: 50 проверок поиска, идентификаторов, recent/frequent порядка, лимитов, JSON, повреждённых настроек и сохранения/очистки UserDefaults.
- На macOS: компиляция Swift 6 с warnings-as-errors и отдельный AppKit-харнес с реальными меню, окнами, field editor и target/action. Проверяются native-controls, nil-target dispatch, запрет устаревших действий, история, IME, RU/Caps Lock, повторный `⌘K` и закрытие окон.

Последний срез также проверяет видимый menu entry, защиту IME на menu-пути, размер JSON после экранирования и разрешённую геометрию элементов окна. Native-harness сохраняет PNG реального AppKit view в CI artifact; это не сгенерированный макет. Точные результаты каждого запуска находятся в Checks PR.

В Linux/GCC устранены неоднозначные отступы в control-коде, добавлен прямой `<algorithm>` include, VST3 catalog value types доступны non-Apple bridge, тип flags приведён явно, исправлены unused index и сигнатура full-duplex stub. WAV/AIFF tests проверяют на macOS конверсию, а на Linux — явный отказ для неподдерживаемого ресемплинга и полноценный 48 kHz путь. 32-bit AIFF fixture использует безопасную 64-bit арифметику. Алгоритмы DSP и проектный формат не менялись. Сохранены `-Werror`, sanitizer и весь CTest/e2e набор. CMake и bundle берут версию из VERSION.

Ручные visual, физические keyboard/IME и полный VoiceOver audit остаются открытыми. Accessibility labels/help и системные текстовые controls добавлены, но это не замена проверке с VoiceOver.

## Следующие незакрытые задачи

Пользовательские aliases, единый command registry для действий без пункта меню, project-context команды с параметрами и палитра музыкальных намерений. История не подменяет эти отдельные задачи. Reference A/B из продуктового документа также остаётся отдельным направлением.
