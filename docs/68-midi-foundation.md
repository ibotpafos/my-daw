# 68. MIDI-фундамент (срез 1.40.0)

## Что это
MIDI-фундамент: нотная модель данных, хранение, C-ABI, доставка событий в рендерер и VST3-хостинг, вход CoreMIDI и табличный редактор в приложении. Согласно решению владельца от 2026-09-15 собственные плагины не пишутся — звук нотам дают сторонние AU/VST3-инструменты; этот срез проводит событие по всем контурам исполнения от модели до хоста. Аудиогенерации собственных тембров здесь нет и не будет.

## Модель (`engine/domain`)
`MidiNote{start,length,pitch,channel,velocity}` и `MidiClip{start,length,notes,track}` в `Track.midiClips` (координаты нот — relative к клипу). Валидация: клипы на треке не пересекаются (касание разрешено — следствие split), нота целиком внутри клипа, pitch 0..127, channel 0..15, velocity 1..127, длина ноты ≤ 480000 кадров (10 с), границы клипа ≤ 2^40, не более 64 клипов на трек и 65536 нот в проекте. Команды expected-revision с no-op: addMidiClip, removeMidiClip, setMidiNotes (полная замена — семантика редактора), moveMidiClip, trimMidiClip (рост окна сдвигает относительные ноты, сужение удаляет непоместившиеся целиком), splitMidiClip. Сплит через тело ноты создаёт две части с сохранением суммарной длительности и параметров. Правая часть перезапускается на разрезе (не tie/legato); Undo возвращает исходную ноту. Контракт обновлён в [редакторе групп](arrangement-mixed-groups.md). Трек с нотами и без аудио валиден — это MIDI-дорожка.

## Хранение
Черновик `user_version` 15→16: таблицы `midi_clips(track_id,position,start,length,lane, PK(track_id,position))` и `midi_notes(track_id,clip_position,position,start,length,pitch,channel,velocity, PK(...,position))` — реляционно в стиле sends/automation, запись в той же транзакции. Черновики ≤15 открываются с пустым MIDI (гейт `formatVersion>=16`, проверено тестом даунгрейд-прагмы); читалка проверяет порядок, диапазоны и лимиты до `validate()`. `specs/project-v0.sql` — исторический v0-пример, не затрагивался; актуальную схему описывают этот документ и storage.cpp.

## C-ABI (`engine/bridge`)
`daw_midi_note`/`daw_midi_clip` — версионированные POD (префикс struct_size+version, 32 байта). Команды: `daw_add_midi_clip`, `daw_remove_midi_clip`, `daw_set_midi_notes`, `daw_move_midi_clip`, `daw_trim_midi_clip`, `daw_split_midi_clip`; запросы: `daw_get_midi_clip_count` и страничный `daw_get_midi_clip(note_offset,capacity≤8192,&written)` — `out.note_count` это всего в клипе, `written` — за вызов; клипы больше 8192 нот читаются постранично. Полная замена через `daw_set_midi_notes` теперь принимает до `DAW_MIDI_NOTES_PER_REPLACEMENT` (65536) нот одной атомарной командой; add/append остаются ограничены 8192. Общий бюджет проекта проверяет domain. Контракт редактора и проверка save/open/Undo описаны в [MIDI edit safety](piano-roll-edit-safety.md). ABI-валидация (struct_size/version/null/capacity) не дублирует доменную; `guard()` транслирует доменные ошибки в коды без потребления ревизии. MIDI-мутации намеренно не дёргают resetTransport: транспорт считает аудио-длину, пока нет instrument-source.

## Рендер-план (`engine/audio`)
`MidiTrackPlan` (renderer.hpp): на prepare строит для каждого ординала трека отсортированные absolute-пары on@`clip.start+note.start` / off@`+note.length`; при равном кадре off идёт раньше on (касание клипов корректно). `drain(blockStart,blockEnd,out,capacity)` выдаёт точные `sampleOffset`; переполнение буфера (1024 события/блок) не теряет события — курсор стоит, следующие блоки отдают с clamp offset 0 (поздно, но без потерь). `wrapCutOffs` по bitmask 16×128 звучащих нот: при loop wrap нота, закрытая после loopEnd (её off в лупе недостижим), получает синтетический velocity-0 off на offset 0 нового прохода, затем reset перематывает курсор — нота переигрывается с начала; ни застреваний, ни обрезанных аккордов. Хвосты за пределами проекта и bus/master-цепочки MIDI не получают (документировано). События передаются шестым аргументом `process()` всем звеньям цепочки инсертов трека. Ограничение среза: трек без аудио не имеет голосов и не рендерится — audible-плеер MIDI-дорожек включится аркой instrument-source (AU MusicDevice / VST3-instrument insert).

## Хостинг VST3
Контракт `PreparedMidiEvent{sampleOffset,channel,pitch,velocity,noteOff}` + 6-й параметр `process(...)` с дефолтом — обратная совместимость всех реализаций. Wire-протокол managed-runtime v1→v2 (хендшейк отклоняет несогласованного пира; host и helper всегда из одного дерева): `MidiEvent` POD-зеркало, ≤512 событий на блок. Хост валидирует offset/ch/pitch/velocity — при ошибке fault без публикации запроса (ноты не исчезают молча), переполнение → DryFallback. In-process путь собирает `BoundedEventList` (512 слотов, ноль аллокаций в RT) по фактической раскладке SDK (`busIndex/sampleOffset/ppqPosition`; у `NoteOffEvent` длины в SDK нет). Fake-плагин в `vst3_runtime_isolation` эхо-кодирует принятые события в аудио (frame-accurate по left, mixed-radix поля по right) — доставка проверена через границу процессов; доставка в живой .vst3-синт — физический гейт. Скан VST3 сохраняет subCategory и флаг Instrument (кэш bump 1→2, старые кэши пересканируются). AU: непустой MIDI-канал явно отвергается — MusicDevice отдельная арка.

## Вход (CoreMIDI)
`engine/platform/macos/midi_input.{hpp,cpp}`: `listMidiInputDevices()` (без бросков, headless → пусто), `MidiInput::open/close/poll/dropped` — CoreMIDI read-thread декодирует short-пакеты в lock-free ring 4096 (drop-oldest + точный счётчик), контроль-тред дренирует; ни чего не исполняется на audio-тред. Running status с resync по байту, 0x90 velocity-0 → note-off, CC/pitch-bend/program/system пропускаются без потери синхронизации, sysex обрывает разбор пакета (v0). hostTime (mach absolute) → наносекунды → кадры 48 к чистой функцией. Миграция на MIDIEventList (MIDI 2.0) — будущая арка; живое MIDI-железо — физический гейт.

## UI v0 (табличный редактор)
`PianoRollView.swift` + инспектор: кнопка `＋ MIDI` в toolbar и меню «Добавить MIDI-дорожку» (дорожка + рабочий клип 0–10 с), popup клипов, таблица нот (Начало/Длит. мс, Нота с парсером `C4`/`A#5`/число, Vel), `+ Нота` на playhead (C4, 480 кадров, vel 100, clamp в клип), `− Удалить` по строке; правка = полная `daw_set_midi_notes`-замена с откатом UI при доменном reject, чтение с paging по 8192, undo существующей кнопкой. Редактор скрыт без клипов и неактивен во время записи.

## Управление клипами из инспектора (1.61.0)

Поп-ап «MIDI-клипы» в пиано-ролле дополнен парой кнопок «+ Клип» / «− Клип»: первое пустое четырёхтактовое (192 000 фреймов) вставка `daw_add_midi_clip` на позиции воспроизведения со снапом к половине такта (48 000), удаление — `daw_remove_midi_clip` выбранного индекса. Движковые команды и их гейты (ABI, ненулевая длина, потолок 64 клипа на дорожку, undo-цепочка) существовали с MIDI-фундамента и покрыты `midi_model`/`midi_bridge`; волна добавила только вертикальный UI-вход: после добавления выделяется новый (последний) клип, после удаления индекс сбрасывается и инспектор перезагружается. Кнопки gated по `editorEnabled` (запись/редактирование блокируют). Голосовые метки и подсказки — через `setAccessibilityLabel/Help` как у соседних контролов.
