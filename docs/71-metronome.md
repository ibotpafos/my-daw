# 71. Метроном (срез 1.43.0)

## Что это
Клик-трек из темпо-карты: удары на битах с акцентом на начала тактов, синтезируемые в реальном времени внутри renderer. Runtime-флаг (как `playing`), НЕ часть проекта — состояние транспорта.

## Реализация (`engine/audio`, весь код в renderer.*)
`setMetronome(bool)` — atomic; `renderInternal(...,suppressMetronome)` — публичный `render()` подавления не делает, экспортный путь вызывает подавляющий вариант. Смесь клика — сразу после мастер-цепочки: позиция = абсолютный кадр − blockStart, фаза синуса от абсолютного кадра (blip через границу блока бит-идентичен). Арифметика только через `State::frameAtBeats/beatsAtFrame` — дублирования темпо-логики нет; timeline-копия карты берётся на prepare. Такт = `numerator×4/denominator` четвертных; сетка бит непрерывна от frame 0, перезапускается только при смене numerator. Синтез: 5 мс, 1000 Гц (акцент 1500), −18 dBFS, cos²-огибажка.
RT-контракт: `beatBlips` — фиксированный stack-массив 128 (никаких аллокаций в CoreAudio-коллбэке), исключение `frameAtBeats` за границей перехватывается и обрывает обход; подавление в экспорте доказано grep-списком вызовов: экспорт — только `export.cpp:264 renderExport` (+ renderTail без клика по построению), live-коллбэки duplex/output клики слышат осознанно.

## Тесты
`daw_audio_tests` (CTest `audio_render_storage`): (a) 8 blip-окон с peak>0.05 на L=R, тишина между — точные нули; (b) off == контрольный memcmp, on != контрольный; (c) карта {0:120, 96000:60} — интервалы удваиваются, абсолютная тишина между; (d) `renderExport` при metronomeOn побайтово == контрольный; (e) акценты различаются zero-crossing-метрикой (1000 Гц → 9 переключений в окне, 1500 → 14, ассерты [7,11]/[12,17]).

## Открытые гейты
Слуховая приёмка клика на железе (offline-адаптер доказывает DSP, не задержку), pre-roll до записи (следующий слой: клик до старта take), bridge/UI-переключатель (в мосту функции намеренно нет — арка проводки отдельным срезом), клик минует мастер-инсерты (сознательное решение «после всего»).
