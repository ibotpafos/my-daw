# Arrangement editing: инструменты, жесты и навигация

## Цель и порядок реализации

Рабочая область должна давать один понятный путь от выбора клипа до результата,
без необходимости открывать отдельную панель ради каждого перемещения.
Ориентир по взаимодействию — Studio One / Logic Pro, не обещание полного паритета.

| Этап | Содержание | Статус этого изменения |
| --- | --- | --- |
| 1. Общий слой взаимодействия | Инструменты, курсоры, фокус, предсказуемые жесты, отмена предпросмотра | Реализован |
| 2. Прямое редактирование | Аудио и MIDI на таймлайне через существующий C ABI, групповое аудиоредактирование | Реализован в границах текущих команд, см. ниже |
| 3. Навигация | Рука, zoom у мыши, fit, границы клипов, клавиатура | Реализован |
| 4. Модель клипов и буфер | Снимки клипов, повторная вставка, вырезание групп одной дорожки, перенос чужих аудиоисточников и удаление последнего региона | Реализован следующий срез: [контракт буфера](96-clip-clipboard.md). [Смешанные группы](arrangement-mixed-groups.md): move/copy/delete/nudge реализованы; смешанный clipboard остаётся следующим этапом |
| 5. Расширенный монтаж | Slip, stretch, glue/consolidate, ripple, range cut/copy, loop handles, crossfade drag | После этапа 4; не реализован этим PR |
| 6. Приёмка | Большие проекты, реальные устройства ввода, accessibility, запись и воспроизведение | Нативные регрессии добавлены; ручная приёмка отдельно |

## Управление

Инструменты принадлежат окну, не проекту. Клавиши работают, когда фокус находится
на дорожке аранжировки; ввод имени, поиск, инспектор, микшер и Piano Roll не
перехватываются. Используются физические коды клавиш, включая цифровой блок:
раскладка RU/EN не меняет выбор инструмента.

| Клавиша | Инструмент | Действие |
| --- | --- | --- |
| 1 | Указатель | Выбор; перенос за тело; обрезка за левый/правый край |
| 2 | Выделение | Рамка выбора клипов по нескольким дорожкам |
| 3 | Ножницы | Разделить клип в позиции щелчка с учётом сетки |
| 4 | Ластик | Удалить клип через существующую команду модели |
| 5 | MIDI-карандаш | Нарисовать пустой MIDI-клип на MIDI- или пустой дорожке |
| 6 | Mute | Включить/выключить mute аудиоклипа |
| 7 | Рука | Переместить видимую область в двух направлениях |
| 8 | Масштаб | Щелчок: приблизить; Option-щелчок: отдалить; drag: приблизить диапазон |
| 9 | Фейды | Левая/правая половина аудиоклипа редактирует fade-in/fade-out |

Option-drag указателем копирует выбранный клип или всю группу в место отпускания. Shift временно
отключает привязку к сетке при перемещении, обрезке, разрезании и рисовании.
Command-/Control-щелчок добавляет или убирает клип из выделения. Shift-рамка
инструментом 2 добавляет клипы к выделению. Обычный drag выбранного клипа
сохраняет выделенную группу. Двойной щелчок по MIDI открывает существующий
нижний редактор.

| Команда | Действие |
| --- | --- |
| Command-C / C | Копировать один клип или группу одного типа с одной дорожки |
| Command-X | Вырезать выделенные клипы сразу, одной операцией Undo |
| Command-V / V | Вставить снимок клипов у playhead на дорожку с фокусом; можно повторять |
| Command-D / D | Дублировать всё выделение после его полного временного диапазона |
| Delete | Удалить выделение; Cmd-Delete остаётся удалением дорожки |
| S | Разделить выбранный клип у playhead |
| M | Mute выбранного аудиоклипа |
| Command-A | Выбрать все клипы дорожки с фокусом |
| Command-Shift-A | Выбрать все клипы проекта |
| Option-Left / Option-Right | Сдвиг клипа/поддерживаемой группы на шаг сетки |
| Z / Shift-Z | Показать выделение / весь проект |
| Tab / Shift-Tab | Следующая / предыдущая граница клипа |
| Home / End | Начало / конец воспроизводимого проекта |
| Left / Right | Сдвинуть playhead на шаг сетки |
| Up / Down | Перейти к соседней дорожке |
| Command-wheel / pinch | Масштабировать вокруг позиции мыши/жеста |
| Shift-wheel | Горизонтальная прокрутка |
| Escape | Отменить текущий предпросмотр |

Существующие меню, Command-S, Command-Z/Shift-Command-Z, Command-K, транспорт,
импорт файлов и полоса цикла сохранены. Масштаб ограничен диапазоном 1…256.
Панель адаптируется к узкому окну: цифры остаются видны, второстепенные команды
доступны через «Ещё»; ничего не исчезает из командной модели приложения.

## Семантика и безопасность

- `ArrangementEditingModel` содержит только расчёты и типы; не импортирует AppKit
  или аудиодвижок. Целые кадры, проверка границ, единый delta для группы.
- `ArrangementEditingController` принадлежит `DAWWindow` через узкий протокол `ArrangementWindowEditing`.
  Захватывает исходную revision, document UUID, координату начала и выбранные
  клипы. Во время drag рисует прозрачный overlay, не пишет в модель и не строит
  аудиограф. При отпускании вызывает одну существующую команду.
- Escape, щелчок без перемещения, смена инструмента и конфликт revision не
  создают Undo. Обновление документа отменяет старый жест. Операции записи
  блокируют редактирование. Неподдерживаемая групповая команда отклоняется
  целиком, а не выполняется частично с несколькими Undo.
- Новая команда привязки использует `anchor + N * quantum`, а не просто anchor
  темпо-точки. Буфер не вызывает старый небезопасный paste по индексу без проверки.
- Буфер хранит неизменяемое содержимое в сессии: геометрия и свойства аудио,
  удерживаемые immutable-источники, MIDI-ноты/цвет/слой. Изменение или удаление
  оригиналов, Undo/Redo и успешная вставка не очищают буфер. Новый/открытый
  документ очищает буфер. Подробности в [контракте буфера](96-clip-clipboard.md).
- Ошибки C ABI для новых жестов показываются в строке состояния без модального
  окна. Аудио редактируется только на UI/owner thread. Формат проекта и DSP не меняются.

## Существенные ограничения существующей модели

Эти пункты обнаружены при аудите и **не объявляются готовыми функциями**:

1. Аудиоперенос/копирование больше не требует общего исходника: источник
   присоединяется к существующей таблице base/takes целевой дорожки. Лимит —
   16 источников/тейков на дорожке; глобальный media pool ещё не реализован.
2. Последний аудиоклип теперь можно удалить/вырезать/перенести. Дорожка,
   исходники, эффекты и routing сохраняются; Undo возвращает регионы.
3. Copy/cut/paste через буфер остаются однотипными, с одной дорожки. Но drag,
   Option-drag, duplicate, nudge и Delete уже атомарны для смешанных групп
   нескольких дорожек: [контракт](arrangement-mixed-groups.md).
4. MIDI trim удаляет ноты вне нового окна; это восстанавливается через Undo,
   но не простым обратным растягиванием края. MIDI split делит продолжающуюся
   ноту на две части, правая перезапускается. Split зацикленного аудиоклипа
   по-прежнему отклоняется ядром.
5. Перекрытие регионов ограничено правилами существующего crossfade. Новый слой
   не делает скрытое стирание, ripple или наложение поверх соседнего клипа.
6. Рамка — выделение **клипов**, не редактируемый временной фрагмент. Текущая
   полоса цикла остаётся отдельной. MIDI mute, slip, time-stretch, glue, range
   cut/copy, перенос на новую дорожку при drop и непрерывный stationary-edge
   autoscroll не входят в этот этап.

### Оставшийся этап: критерии приёмки модели

- Смешанный snapshot-буфер Copy/Cut/Paste для нескольких дорожек; атомарные
  drag/delete/duplicate/nudge уже реализованы отдельно от буфера.
- Независимый глобальный пул источников вместо ограниченной таблицы base/takes,
  без потери comping, save/reopen, effects и routing.
- Недеструктивное окно MIDI-региона; контракт разреза с retrigger уже реализован.
- После этих гарантий — range editing, ripple, slip, stretch, glue, crossfade
  и loop handles. Для destructive/render-команд нужны отдельные backend tests.

## Проверки

`tests/arrangement_editing_model_tests.swift`: числовые границы, invalid/NaN,
RU/keypad tool mapping, snap, источник, фейды и групповой delta; 4 000
детерминированных итераций инвариантов. Число assertions не равно числу
независимых пользовательских сценариев.

`tests/workspace_arrangement_editing_tests.swift`: настоящее `DAWWindow.sendEvent`
и C ABI — выбор инструментов, защита текстового ввода, drag preview/Escape,
MIDI move/copy/trim/split/draw/delete, Undo/Redo, сохранение нот и выделения,
record/capture guards, stale projection и revision/document conflicts, zoom/Tab.
Продолжение в `workspace_clipboard_tests.swift` проверяет новый многоразовый буфер,
настоящее вырезание и общий маршрут меню/клавиатуры.
Включён в существующий `scripts/test-workspace-ui.sh`; не заменяет его тесты.

На Linux выполняются Foundation-модель, документация/manifest и синтаксический
разбор Swift. Полный AppKit typecheck, сборка и события требуют macOS CI.
Проверка drag мышью/трекпадом, VoiceOver, темпо-переходов на реальных проектах,
производительности на 256 дорожках и фактического аудиовыхода — отдельная ручная
приёмка; генерация изображения не считается проверкой интерфейса.
